PROBLEM IDENTIFIED:
-------------------
The application was experiencing repeated errors when attempting to create 
Feishu streaming cards without the required cardkit:card:write permission.

Error Pattern:
  14:03:00 error feishu-streaming Failed to start streaming session...
  14:03:00 warn feishu-message Failed to start streaming card...
  14:03:06 error feishu-streaming Failed to start streaming session...
  14:03:06 warn feishu-message Failed to start streaming card...
  [repeated every 6 seconds]

Issues:
  • Excessive log spam (8+ errors every 6 seconds)
  • No clear resolution guidance
  • No fallback mechanism
  • Poor user experience

SOLUTION IMPLEMENTED:
--------------------
Created a comprehensive error handling system with 4 key components:

1. SMART PERMISSION DETECTION
   ✓ Detects missing cardkit:card:write permission
   ✓ Caches permission state to avoid repeated checks
   ✓ Configurable cooldown period (default: 60 seconds)
   ✓ Automatic retry after cooldown expires

2. GRACEFUL FALLBACK MECHANISM
   ✓ Automatically switches to standard message delivery
   ✓ Ensures message delivery succeeds
   ✓ Transparent to end users
   ✓ No interruption in service

3. IMPROVED LOGGING
   ✓ Error logged once with clear guidance
   ✓ Provides auth URL for permission grant
   ✓ Debug-level messages during cooldown
   ✓ Full timestamps (YYYY-MM-DD HH:mm:ss)

4. CONFIGURABLE ARCHITECTURE
   ✓ Environment variable support
   ✓ Constructor-based configuration
   ✓ Easy to adjust per environment
